# 使用 BotOrgHQ 主动执行

在 BotOrgHQ 左侧打开公司工作台，选择公司。先为 Chief 和负责执行的 Bot
配置可用的 DSH 模型。已有公司的自治默认是 **OFF**。

1. 在 **自治设置** 选择策略范围和模式。先用 **SUGGEST**，明确允许
   `model.plan` 和公司数据范围。确认建议后，可以切换为 **SUPERVISED**
   或 **BOUNDED_AUTO**，逐项授权 `org_delegate`、`company.evidence.read`、
   `model.work` 和 `task.result.submit`。
2. 在 **长期目标** 填写目标、意图、验收标准和检查间隔，并授权启用。从此
   DSH 本机宿主运行时会按目标复查，无需发送新的聊天消息。
3. 在 **触发器** 添加指定时间、间隔、Heartbeat 或 Cron。例如
   `0 9 * * 1-5` 配合 `Europe/London`，表示当地工作日 9 点。也可订阅
   内部事件和验签的 GitHub Webhook。恢复后可选择跳过或只补最近一次。
4. **主动活动** 显示机会、不行动的原因、工作流、证据和审计。
   **任务看板** 显示实际任务。证据引用完整与验收通过分开展示。
   在主动活动里可审查结果、暂停或取消任务，以及调整尚未开始的任务负责人。
5. 在 **人工审批** 审查待执行动作。批准只适用于该次精确动作，目标、授权或
   部门策略变化会使受影响的动作重新评估。审批默认 24 小时过期。
6. 在 **自治设置** 可暂停公司、部门或 Bot。暂停不会删除现有计划。
   修改过目标或策略的旧动作保留记录，重新触发目标可依新版本规划。

开启公司策略时请明确保留预算。部门和员工只能缩小权限。设定货币限额时，
未能获得可信模型定价会阻止模型调用。可按 token、次数、时限和并发量授权。
影子模式会保留计划评估供审查，且不会委派或提交任务结果。

在桌面更新窗口的 **后台运行与通知** 可启用关闭主窗口后继续运行。Windows
通过托盘进入，Mac 通过 Dock 恢复窗口。退出应用或休眠会停止本机调度。
恢复时检查过时事件和执行授权。运行中的未知结果需要检查后再恢复。
通知正文只显示有新活动，详细内容保留在应用内。

## GitHub 或通用 Webhook

设定 `BOTORGHQ_WEBHOOK_PORT` 和独立的 `BOTORGHQ_WEBHOOK_*` 密钥变量，
每个密钥至少 24 个字符，再启动宿主。选择 GitHub 触发器，填入准确的
`owner/repo`、订阅事件和环境变量名，同时将相同的 `github:owner/repo`
添加到公司策略和目标数据范围。Webhooks 的详情会显示路径。
只把该路径通过可信的 HTTPS 代理转发到本机监听端口。GitHub 配置 JSON
负载并使用同一密钥。受支持事件为 push、issues、pull_request、workflow_run。
签名错误、重复报文、过时和不匹配的仓库都不会触发新工作。
停机期间的失败传递可在 GitHub 中重投。也可配置只读的 `BOTORGHQ_GITHUB_READ_*`
环境变量和触发器的补偿拉取选项。引擎保存游标并对恢复窗口内 GitHub 仍提供的事件去重。

通用 webhook 使用 `x-botorg-id`、`x-botorg-time`（毫秒 Unix 时间）和
`x-botorg-signature`（`sha256=<hex>`），签名内容为
`timestamp + "." + deliveryId + "." + rawBody`。密钥值不进入设置或审计。
