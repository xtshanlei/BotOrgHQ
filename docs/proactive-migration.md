# 升级、导出和恢复

从 v0.3.0 升级时使用现有 DSH 数据目录。桌面更新器会先停止宿主，再备份。
新版首次启动创建一个独立的 `bot-org-hq/proactive.sqlite`，现有组织 JSON、
会话、配置、Bot 名册与记忆仍由原本的组件管理。所有旧公司最初为 OFF。
新数据库由内置 Node SQLite 打开，桌面版本不增加额外的 SQLite 原生模块。

## 搬到另一台电脑

桌面中打开 **帮助 → 导出或导入数据…**。输入至少 12 个字符的恢复密码，
选择 **导出加密归档…** 和保存路径。选取归档并用同一密码导入即可。
归档为带完整性校验的 AES-256-GCM 文件，保存完整本地 DSH 树，包括配置、
对话、附件、Bot、公司、部门、任务、记忆、自治记录、凭据文件和桌面偏好。
密码单独保存。升级器的系统加密 GitHub Token 需要在新机器上重新设置。

应用会把旧数据目录保留在原路径旁边，验证归档后才切换。导入后主动任务和
未决审批被冻结，以免两台机器重复执行。确认原宿主已退出，再在新机器上
恢复公司授权并重新规划。系统钥匙串中的登录、未写进 DSH 目录的环境变量、
外部工作文件夹和绝对路径需要在新机器上单独配置。归档不读取目录外的数据。
跨 OS 的链接和路径以目标系统支持为准。

DSH 插件版可在**完全退出 DSH 后**通过以下命令导出或导入。路径指向安装
包或源码中的脚本。密码由标准输入传入，应使用系统的隐藏输入方式。

```sh
node scripts/profile-transfer.mjs export /absolute/path/to/dsh /absolute/path/profile.bohq
node scripts/profile-transfer.mjs import /absolute/path/to/dsh /absolute/path/profile.bohq
```

## 回滚

先退出宿主。使用桌面更新前的备份，或导入时留下的 `dsh.before-import-*`
目录，恢复同一用户数据路径下的 `dsh`。保留当前数据副本，再换回旧版应用。
v0.3.0 仍能读原有组织 JSON。回退到旧版期间无法在界面中处理主动工作；
重新升级前先确认是否需要保留新版的数据库和工作历史。
